# TaxPrep Local — 本机报税资料核对工作台 v0.6

这是一版可运行的独立工具，用来整理客户 PDF、核对有限的常见收入字段，并导出工作底稿。界面为中文，原始英文资料可在本机识别。它不计算税额，不直接修改 ProSeries 文件，也不提交报税。

## Windows 启动

1. 安装 Python 3.10 或更新版本，可同时安装 Python Launcher；启动脚本也支持 PATH 中的 python。官方入口：https://www.python.org/downloads/windows/
2. 解压整个程序包到固定目录。不要直接在 ZIP 内双击运行。
3. 双击 `run_windows.bat`。第一次需要联网安装 PyMuPDF；安装完成后会打开浏览器。
4. 点击“载入合成演示资料”可以先练习，无需真实客户文件或 OCR。
5. 浏览器地址是 `http://127.0.0.1:8765`。保留命令行窗口，关闭它会停止程序。

扫描件额外需要 Tesseract OCR。按照官方文档 Windows 部分安装，并保留 `eng`（英文识别）及 `osd`（文字方向）数据：
https://tesseract-ocr.github.io/tessdoc/Installation.html#windows

默认会寻找 `C:\Program Files\Tesseract-OCR\tesseract.exe` 或 PATH 中的 `tesseract`。其他位置可在启动前设置：

```bat
set "TESSERACT_CMD=D:\Tools\Tesseract-OCR\tesseract.exe"
run_windows.bat
```

没有 OCR 也能启动、查看原页、读取数字 PDF、手工录入和导出。安装 OCR 后点击“继续识别缺失页”，不会覆盖已有记录；如果某页已经建立记录，需另建测试工作区重新上传以重新验证 OCR。

## 员工实际操作

1. 新建客户，用客户代号和税务年度区分工作区。测试人员可先阅读 [测试指南](../testing/TESTER_GUIDE.md) 并载入合成演示。
2. 上传客户原始资料；已经完成的税表请选“已完成税表”。两种用途的记录分开。
3. 等待识别。文件按顺序逐页处理，复杂扫描可能需要数分钟。每份限制 50MB、200 页。
4. 点选左侧页面，在原页/识别文字之间切换。右侧金额只是候选值，不代表正确；未识别处保持空白。
5. 点击金额可定位有版面证据的原页位置。核对表格类型、本人/配偶/共同归属、付款方和金额，补充遗漏项目到备注。审核人确认空白字段后，点“核对通过”。
6. 同页有多种表格可添加多条记录。封面、说明、重复副本、补充汇总、8879、未来年度预估税凭单等，需要确认后排除整页或对应记录。
7. 逐页确认用途。证券资料尤其需要明确选择汇总或明细，不可两套都计入。软件不会替你决定汇总申报是否满足条件。
8. 导出 JSON 草稿，或导出已核对的原始收入记录 CSV。CSV 只导出记录已审核且所在页面用途已确认的子集；它不是完整性证明，不是 ProSeries 的导入文件。
9. 打开“记录任务队列”，按状态、表格、归属或关键词筛选，直接打开指定记录。记录中的“修改记录”可查看已保存的字段变更；未保存输入不在历史中。
10. 展开“金额核对与待办”检查算式冲突和有限字段的 1040 对照。存在错误时不能导出已核对 CSV，仍可导出 JSON 草稿。
11. 点击“录入底稿 / 打印”，下载按表格分组的可打印 HTML；“已核对”范围只包括记录和页面都已确认的子集。底稿不是 ProSeries 导入文件。
12. 点击“测试反馈 / 计时”记录操作用时和问题，按客户导出反馈。
13. 使用“备份全部工作资料”保存数据库、原件和页面图片。

## 自动完成 / 仍需人工

| 功能 | 当前行为 |
|---|---|
| 本机 PDF 读取、页面图片、文字识别 | 已实现；扫描方向自动检测可能失败，须查看原页 |
| PDF 重复上传 | 同一客户中用文件指纹阻止相同文件再次导入；不同扫描副本不能靠指纹去重 |
| 表格分类 | 规则识别常见 W-2、SSA-1099、1099-INT/DIV/B；误分和漏分可人工修正 |
| 金额提取 | 支持部分同行和版面位置提取：W-2 六项、SSA-1099、一种 Schwab 证券分类汇总；字段和版式不全 |
| W-2 多联副本 | 同一页默认仅建一条 W-2；跨页/跨文件重复仍需人工检查 |
| 已完成 1040 对照 | 支持部分关键行的版面提取；审核后对照工资、普通/合格股息、社安金总额；州税未适配 |
| 核对与测试 | SSA/证券算式、重复候选、证券汇总/明细冲突、待办、测试计时及反馈 |
| 税务计算、扣除资格、跨账户洗售、成本追踪 | 未实现 |
| ProSeries 自动输入 / 导入 | 未实现，接口和版本尚未验证 |
| 正式电子申报 / 付款 | 未实现 |

字段模板仅是常见字段子集：W-2 的 Box 12/13/14、多州行、1099 的其他特殊项目、证券明细日期等不能视为已覆盖。发现未覆盖项目时先记入备注，继续在原报税软件中核对处理。金额保留分位；空白不自动当成零。

字段按 2025 年示例起步验证；其他年度、其他州税、ProSeries Basic/Professional 与不同年度版本均未完成兼容性验证。可新建其他年度工作区进行资料整理，但不能据此推断其税表对应关系已正确。

## 数据位置、备份与恢复

- Windows 默认：`%LOCALAPPDATA%\TaxPrepLocal`；数据库是 `taxprep.sqlite3`，原始 PDF 和预览在 `documents`。
- 修改位置：启动前设置 `TAXPREP_DATA_DIR`，或 `python app.py --data-dir D:\TaxPrepData`。
- 程序只绑定 127.0.0.1，不应改成面向局域网/公网的服务。当前没有员工账户体系；审核人只是记录姓名/代号，不能证明真实登录身份。程序以进程锁阻止两个实例同时使用同一数据目录。
- 处理客户资料不调用云端 OCR、模型或其他网络服务。首次安装依赖需要联网。
- 本机数据和导出/备份未加密，使用电脑已有的磁盘加密和文件访问控制。备份包含完整原件和修改历史。
- 恢复时双击 `restore_windows.bat`，选择资料备份 ZIP，再选择一个父目录；工具会验证并创建新的恢复目录，不覆盖现有数据。恢复完成后先关闭旧程序，再双击恢复目录中的 `start_restored.bat`。
- 也可只检查备份：`python -X utf8 -m taxtracker.operations.restore_backup --backup backup.zip --check-only`。命令行恢复：`python -X utf8 -m taxtracker.operations.restore_backup --backup backup.zip --destination D:\TaxPrepRestored`，然后 `python app.py --data-dir D:\TaxPrepRestored`。
- 恢复会核对 ZIP 路径、数据库完整性、原始 PDF 指纹和页面预览；支持旧版无清单的资料备份。程序安装包不是资料备份。
- 正在识别时暂不生成备份，待识别完成后再点。已中断/失败任务可随已有记录备份，恢复后继续识别。本版备份/恢复上限为 2GB、20000 个文件、单文件 128MB。
- Windows 恢复窗口依赖 Python 的 Tcl/Tk。没有图形组件时可使用上述命令行方式。新目录的启动脚本指向当前程序文件夹，移动程序后可改用 `--data-dir` 启动。
- 同一条记录被其他窗口修改时，旧窗口保存会被拒绝，避免覆盖核对结果。

## 从旧版升级

1. 在旧版下载“备份全部工作资料”，然后停止旧版命令行窗口。
2. 将 v0.6 解压到新目录，再运行新目录里的 `run_windows.bat`。默认数据目录不变，旧资料和审核结果会保留；首次启动自动补充缺少的表，v0.6 新增应交资料表。
3. 不要同时运行旧版和新版。若提示数据目录正在使用，先关闭旧程序。
4. 旧页面不会自动重写。待核对记录可点击“重新提取（仅补空白）”；手填金额保留。已审核记录需先另存待核对，再获取新建议，且仍需人工确认。
5. 安装问题可双击 `check_windows.bat`，查看 Python、PyMuPDF、OCR 和语言数据状态。

本程序不需要 OpenAI API Key 或激活码。ProSeries 是另外的软件，本工具尚未连接它。

## 开发运行与检查

```sh
python -m venv .venv
# Windows: .venv\Scripts\python.exe -m pip install -r requirements.txt
# macOS/Linux: .venv/bin/python -m pip install -r requirements.txt
python -m pip install -r requirements.txt
python app.py --no-browser --port 8765
python -m unittest discover -s tests -v
```

更换端口：`python app.py --port 8766`。运行环境已测试 Python 3.12.14、PyMuPDF 1.26.6、Tesseract 5.3.4；Windows 启动脚本尚未在真实 Windows 电脑执行验收。

源码：根目录的 `app.py` 和 `server.py` 是启动入口。业务模块按用途放在 `taxtracker/` 下，`tests/` 保存自动测试，`docs/testing/` 保存测试报告。

## v0.6 应交资料与催收

1. 展开“客户应交资料”，点“添加应交资料”。每个雇主、账户或资料单独登记，选择归属，填写经办人。
2. 收到资料后修改为“已收”，可关联本客户上传的原始文件；关联对照税表或其他客户文件会被拒绝。没有上传的纸质资料也可登记已收。
3. 不适用项目必须填原因。填写已收不等于审核金额，也不会创建收入记录。
4. 下载催资料草稿，仅列出待收项目名称和归属，不带内部备注、经办人或金额。自行检查后，通过约定渠道发送；程序不会发送。
5. 待收项目自动进入复核交接清单。空清单或待办清空不代表客户已交齐所有资料，员工仍需按实际情况判断。
6. 本次新增资料表包含在全部资料备份中。升级须先备份并关闭旧程序；请使用 v0.6 管理新增资料项目。
