# 测试人员快速指南 · v0.6

先找两个人：一位熟悉 ProSeries 的报税员工，一位没有参与开发的普通操作员工。先用合成演示练习，再用经过授权的测试副本。

## 安装和首次试用（约 15–20 分钟）

1. 安装 Python 3.10+，解压程序，双击 `scripts/windows/run_windows.bat`。
2. 若启动失败，双击 `scripts/windows/check_windows.bat`。诊断不会读取客户资料，可把输出文字作为安装反馈。
3. 点击左侧“载入合成演示资料”。会新建独立演示客户，并生成 W-2、SSA-1099、1099-DIV 和一页 1040 对照，共四页。全部是虚构数据，演示不需要安装 OCR。
4. 点击页面、金额输入框，观察原页金额是否高亮。对照原件核对金额和归属；合成演示的收入可以选择“本人”。
5. 填审核人，核对空白字段，保存“核对通过”，并逐页确认用途。对照税表也需要审核和确认用途。
6. 展开“金额核对与待办”，检查工资、普通股息、合格股息、社安金合计是否与演示对照一致。整美元舍入差异由状态提示，不代表税额计算已完成。
7. 测试“重新提取（仅补空白）”：在待核对状态手工保留一个金额，清空另一个字段，再点提取；已有手填金额不得被覆盖。补入候选仍须核对保存。
8. 在 SSA-1099 中故意把“已付福利”改错，保存待核对。应出现“已付福利 − 退还福利不等于净福利”提示；存在这类算式冲突时，已核对 CSV 导出会被阻止。改回正确金额。
9. 测试 JSON、CSV 和备份下载。CSV 是整理底稿，不能直接当作 ProSeries 导入文件。
10. 刷新浏览器、停止程序并重新启动，确认资料和审核记录保留。

## 如何记录问题

点击“测试反馈 / 计时”：开始计时 → 完成一项任务 → 停止计时 → 填测试人代号、功能区域、反馈类型和问题内容 → 保存。

建议每条反馈写：

- 程序版本、测试资料代号、页面 / 记录编号。
- 操作步骤。
- 预期结果。
- 实际结果，以及错误值或漏项（不填完整身份号码、账号或密码）。
- 是否能继续完成任务，以及操作用时。

反馈只保存在本机，不会自动发给开发者或客户。测试结束后点“导出本客户测试反馈”，把导出的文件交给负责人。处理后可在工具内标记“已处理”；该状态只是人工标记，不代表程序自动修好了问题。

## 实际业务对照测试

用同一套测试资料分别完成两次：按原来的手工流程整理，再用本工具整理。记录两次用时、漏项数量、错值数量、补录字段和不方便的步骤。

先测 3 类案例：简单工资；夫妻工资 + 社安金；包含券商交易的案例。股票汇总必须由熟悉 8949 分类、成本和洗售处理的员工审核。本版仅适配一种 Schwab 分组汇总版式，其他版式需要手工核对；不是全部券商自动提取。

## 暂不纳入验收

税额计算、扣除资格、跨账户洗售、自动导入 ProSeries、电子申报、全州税表、所有年度及所有版本兼容。这些功能尚未实现或验证。

测试通过的标准是“资料能可靠整理和核对”，不是“可以无人审核报税”。


## v0.6 追加测试

- 用记录任务队列搜索文件/付款方，切换 W-2、SSA-1099、归属和审核状态，确认打开的是指定记录。
- 保存一次修改，打开“修改记录”，确认旧值、新值和审核人能追溯。页面用途不属于此记录历史，应另查页面状态。
- 只审核记录、不确认页面用途，确认它不会进入已核对 CSV 或已核对底稿。确认页面后再导出检查。
- 下载录入底稿，用浏览器打开并打印/另存 PDF；确认待核对版本有明显草稿标识、原始资料和完成税表分开显示。
- 生成资料备份，双击 `scripts/windows/restore_windows.bat` 恢复到新目录。先关闭旧版，再用恢复目录内的 `start_restored.bat` 启动，核对客户、原件、审核人、状态和反馈是否保留。不要删除原目录。
- 如果选择程序安装 ZIP 而非资料备份、选择非空恢复目录，工具应拒绝且保留原资料。Windows 安装和恢复窗口都需要实际电脑验收。


本版新增复核交接清单：展开清单可查看待处理事项、跳转原页及下载 JSON 交接文件。页面确认百分比只表示页面用途确认进度；待办清空不代表资料齐全或可以申报。清单检查已确认但无有效记录的页面、缺失页面、识别未完成、待审核记录及金额冲突。交接文件含客户代号、文件名及部分金额，应妥善保存。升级前备份并关闭旧版，使用原数据目录启动即可；无需更改数据库结构。


新增测试：登记本人 W-2 待收项目，下载催资料草稿；确认草稿不含内部备注。改为已收并关联原始文件，确认待收数减少；改不适用时必须填原因。备份恢复后确认项目保留。
